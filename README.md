# tdrive-aliyunpan

把阿里云盘的文件按计划搬进 [tdrive](https://github.com/dibin666/tdrive)（也就是搬进 Telegram）的插件。

- **任务**：把一个云盘目录映射到一个 tdrive 目录，可按名称正则和文件大小过滤，可选上传后删除云端原件；每个任务可独立选择备份盘或资源库。也可以在浏览器里直接勾选若干个具体文件，只同步这些文件而不是整个目录（勾选可跨目录保留，手动挑选的文件不再受大小和排除规则影响）。
- **同步队列**：每行可勾选，支持批量重试、批量取消和批量删除记录。取消正在传输的文件会真的中断它，并同时作废 tdrive 那边的上传任务，不会留下一个已经取消却还在上传的传输。
- **计划与限额**：每天允许运行的时间窗口、窗口内的重新扫描间隔、每日上传到 Telegram 的字节上限。
- **下载控制**：可单独设置同时从阿里云盘下载到本地的文件数，不影响 tdrive 自身的 Telegram 下载并发；单个文件的 Range 连接数仍遵循 tdrive 性能参数。
- **自动重试**：下载和上传失败都会自动重试，默认最多 5 次，间隔 30 秒起步、每次翻倍、封顶 30 分钟，并带一点抖动避免同一次断网打断的文件一起涌回来。次数用完才记成「失败」等人工处理；手动点「重试」会重新给满重试次数。云端文件已经被换掉或删掉这类重试也没用的错误会直接判失败，不浪费一小时退避。重试的唤醒跟着 30 秒一次的调度走，所以实际等待会比设定值多最多 30 秒。
- **断点续传**：文件按固定大小分块下载，完成的块记进 `.part` 旁边的进度文件，**在途块每 2 秒把已落盘的字节偏移也记进去**（先 fsync 数据再写偏移，保证进度不会领先于真正落盘的内容）。链接过期、网络中断、令牌失效、插件重启之后，重试从精确的字节续上，不会退回块边界重下几十 MB。下载链接的过期时刻直接从 OSS 签名里解出来，剩余不足 1 分钟就提前换新链接，不用先撞一次 403。已经下载完但还没上传成功的文件会直接复用，不会重下；队列里的进度显示的是磁盘上真实有多少字节。
- **本地暂存**：**只有上传成功才会删除本地文件**（可以在「计划与限额」里关掉，改成成功后也保留）。上传失败、下载失败、重试次数用完的传输一律保留已经下好的部分，这样重试不用重新付一遍下载的钱。只有主动「取消」才会连同进度文件一起清掉。
- **下载文件**：插件页面里的一个标签页，列出暂存目录里的每个文件：占了多少磁盘、真正下了多少、属于哪个任务、卡在哪一步、报了什么错。可以单个或批量删除本地文件（队列记录保留，重试会重新下载），也可以一键清理队列里已经没有对应记录的「无主文件」。暂存目录快满时会在这里给出提示。
- **账号**：插件内置 aliyunpan Go/OpenAPI 客户端，直接扫码登录。

所有操作都在 tdrive 网页界面里完成：设置 → 插件 → 「阿里云盘同步」→ 打开。页面里有「同步」「下载文件」「任务」「计划与限额」「账号」五个标签页。

插件不会依赖 aliyunpan 的全局当前网盘。保存任务时选择“备份盘”或“资源库”，插件会自动读取当前账号对应的 drive ID，并在扫描、下载和删除时显式传入，多个任务可以同时使用不同网盘。

源码客户端的登录配置由宿主固定保存在数据卷的 `plugin-data/aliyunpan/config/aliyunpan_config.json` 中，不随插件可执行文件的位置变化；升级或重启插件不会要求重新扫码。旧版本的 `plugins/aliyunpan-data` 会在首次启动时自动迁移，已有的 `settings`、同步队列和配额计数也会继续使用。

## 安装

在 tdrive「设置 → 插件 → 安装插件」里粘贴清单地址：

```
https://github.com/dibin666/tdrive-aliyunpan/releases/latest/download/tdrive.plugin.json
```

这个地址始终指向最新版。因为它不固定版本，tdrive 的「设置 → 插件 → 检查更新」会读到新版本并在插件那一行给出「更新」按钮；也可以像第一次安装一样再粘贴一次地址。插件自身支持 `linux/amd64`、`linux/arm64`、`windows/amd64`、`windows/arm64`，不需要额外安装 aliyunpan 命令行。
